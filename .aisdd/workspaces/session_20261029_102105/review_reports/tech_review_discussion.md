**SQL 分析（核心三条）**

```sql
-- ① 消费主路径 CAS（IM-CORE-002 动态列更新）
UPDATE device_info SET online_status=?, last_sync_time=?, version=version+1, update_time=NOW(3)
 WHERE sn=? AND version=? AND deleted=0;
-- 等值命中 uk_sn（UNIQUE），version 作谓词回表校验 → 单行更新；并发同 SN 由 CAS + 有界退避（±20% jitter）承担
-- 结论：✅ 命中唯一索引，无锁升级风险

-- ② 两层幂等写入
INSERT INTO mq_consume_record (source, msg_id, sn, msg_type, status, ...) VALUES (...);
-- 依赖 uk_source_msg 唯一键冲突（1062）判重；source 进唯一键 → 跨源同 msg_id 不会被误判重复（TC-006-03 专门覆盖）
-- 结论：✅ 正确性锚点落在 DB 唯一索引而非 Redis，符合"Redis 不承担正确性"

-- ③ 流水查询 EP-010
SELECT ... FROM device_info_change_record WHERE sn=? ORDER BY create_time DESC LIMIT ?,?;
-- 🔴 该语句不含分区键 create_time 的 range 条件 ⇒ MySQL 优化器不做分区裁剪，
--    保留期 12 个月即在最坏 12 个分区各做一次 idx_sn_create_time 等值探查再归并排序。
--    原设计文档把它写成"按时间倒序天然裁剪到最近分区"——**不成立**，属事实性错误（评审更正④）
-- 结论：⚠️ 可接受（单 SN 行量有界：假设 43 万条/日 ÷ 10 万设备 < 每设备每日 1 条），
--        但若要"只查最近 N 天"必须把 create_time 范围做成必填入参才能触发裁剪 → 登记为 附录 E #14
```

### ⚠️ 复算时发现技能自身的评分公式有缺陷（S-01，登记而非擅自修改）

独立复算时逐项加了权重列，发现 `tech-review` SKILL.md 定义的 6 维权重是 **25% + 20% + 15% + 10% + 15% + 5% = 90%**，而不是 100%：

```
Σ权重 = 0.25 + 0.20 + 0.15 + 0.10 + 0.15 + 0.05 = 0.90
→ 按技能字面公式 总分 = Σ(维度得分 × 维度权重)，满分实际只有 9.000，不是 10.0
→ 全部维度都拿 8.0（"良好"档上限）时总分 = 8.0 × 0.9 = 7.2 < 8.0，过不了线
→ 想字面达到 8.0，维度平均分需 ≥ 8.89
→ 该缺陷技能自带示例即可复现：SKILL.md L736~743 的示例六项加权求和 = 7.255，而权重列写满"100%"的感觉并不成立
```

**同一份评分在两种口径下的结果不同，且方向相反**：

| 口径 | 第 1 轮 | 第 2 轮 | 对 8.0 线 |
|---|---|---|---|
| 技能字面公式 `Σ(得分 × 权重)` | 6.600 | **7.600** | ❌ 未过 |
| 归一化 `Σ(得分 × 权重) / Σ权重` | 7.333 | **8.444** | ✅ 已过 |

**处置（为什么按字面口径判不通过，而不是擅自归一化）**：
1. 本评审不修改技能定义，也不擅自选一个对自己有利的算法——否则等于把判分标准变成可调参数。按技能 Step 5 原文 `总分 = Σ(维度得分 × 维度权重)` 出分，并如实标注分母缺陷与归一化值。
2. **该歧义不影响本轮结论**：B-01 宪法一票否决独立成立，两种口径下本轮都是**不通过、不锁定**。因此不需要需求方为此裁决。
3. **但它影响下一步的预期管理**，所以必须说清：按归一化口径，第 2 轮的分数已经过线，即**剩下的真实阻塞只有宪法一项**；如果补齐宪法后重跑，分数大概率也能过。反过来说，若按字面口径长期执行，本项目的评审线实际上被隐性抬高了约 0.9 倍（相当于要求平均 8.89 分）。
4. `S-01` 已登记进 `tech_review.json` 的 `scoring_arithmetic_defect`，待需求方或技能维护者裁决修法（补第 7 个 10% 维度 / 把某维权重调高 / 显式归一化）；**本轮不代拟修法**。

> 顺带更正本文件旧表述：自检行原写"权重求和 = 1.00 ✅"是**误记**（我按"六个维度齐全"顺手写的，未真的加过）。复算后是 0.90，已改为如实数字。


> **两个数字都要如实说**：即使第 2 轮冲到 8.0 以上，**只要 `.aisdd/Constitution.md` 仍不存在，本轮就不可能通过**。分数不达标是必要条件之一，不是唯一原因。
